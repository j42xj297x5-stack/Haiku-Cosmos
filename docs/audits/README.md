# docs/audits

Katalog audytów projektu.

## Struktura

- `chronological/` — audyty układane chronologicznie.
- `thematic/` — audyty tematyczne (np. runtime, UI, system kart).
- `thematic/runtime/` — audyty historyczne/evidence po migracjach dokumentacji.

## Zasady wpisów

Każdy większy audyt powinien zawierać:

- `EXECUTIVE SUMMARY`
- listę sprawdzonych plików
- ustalenia
- ryzyka
- rekomendacje
- następny krok
