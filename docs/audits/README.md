# docs/audits

Katalog audytów projektu.

## Struktura

- `chronological/` — audyty układane chronologicznie.
- `thematic/` — audyty tematyczne (np. UI, system kart, wydajność).

## Zasady wpisów

Każdy większy audyt powinien być dopisany do odpowiedniego spisu i zawierać co najmniej:

- `EXECUTIVE SUMMARY`
- listę sprawdzonych plików
- ustalenia
- ryzyka
- rekomendacje
- następny krok
